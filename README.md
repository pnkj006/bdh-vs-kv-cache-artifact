# Overview

This repository contains an interactive educational artifact demonstrating the difference between traditional Transformer KV-cache memory and a BDH-style bounded Hebbian memory system inspired by:

> **Kosowski et al. (2025)**  
> *The Dragon Hatchling: Learning to Reason with Structured Memory*  
> https://arxiv.org/abs/2509.26507

The artifact is intended purely for **education and visualization**.

It **does not** implement the complete BDH algorithm from the paper.

Instead, it visualizes the central intuition:

- Transformer inference memory grows linearly with context length.
- BDH-style memory remains bounded by storing information in a fixed-size synaptic state updated in-place.

---

# Motivation

Large Language Models maintain information using a **Key-Value cache**.

For every processed token, additional key/value vectors are stored.

Therefore,

\[
\text{Memory} \propto \text{Context Length}
\]

This means memory usage grows continuously as longer contexts are processed.

The BDH paper proposes an alternative reasoning architecture where memory is encoded into a fixed-size state rather than continuously storing every token.

This artifact illustrates that conceptual difference.

## Synaptic Matrix Simulation

The artifact visualizes a simplified Hebbian update

\[
W_{t+1}
=
(1-\gamma)W_t
+
xx^T
\]

where

- sparse activations are generated
- exponential decay prevents divergence
- Frobenius norm measures matrix magnitude

The visualization is purely pedagogical.

---

## Interactive Controls

Users can modify

### Activation Sparsity

Controls how many neurons fire.

Lower sparsity

→ fewer active neurons

Higher sparsity

→ denser updates.

---

### Decay Rate

Controls forgetting.

Setting

```
γ = 0
```

shows how the matrix norm can grow without bound.

Increasing decay stabilizes the synaptic state.

---

### Simulation Controls

- Step One Token
- Run to Context Length N
- Reset

# Precomputed Data

The frontend is completely data-driven.

Instead of hardcoding values,

it loads

```
memory_curve.json
simulation.json
metrics.json
```

at runtime.

This allows the visualization to reflect results generated by the simulation backend.

---

## memory_curve.json

Contains

```
tokens
kv_memory
hebbian_memory
```

Used for

- context slider
- memory bars
- memory scaling

---

## simulation.json

Contains

```
frames
```

Each frame stores

```
matrix
norm
step
```

These frames drive the heatmap animation.

---

## metrics.json

Contains summary statistics including

- processed tokens
- final Frobenius norm
- active synapses
- maximum weight
- minimum weight
- mean weight

Displayed in the browser console for verification.
